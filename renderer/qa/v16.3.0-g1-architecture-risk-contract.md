# DE.PULSE v16.3.0 — G1 Scope / Architecture / Risk Contract

## 1. Purpose

v16.3 is **Professional Validation & Learning**, not a new trading engine. It must answer how frozen deterministic decisions behaved after they were made and what can be learned without contaminating historical truth or changing production formulas.

The immutable v16.3 scope is **#8, #18, #19, #20, #26 only**.

## 2. Canonical ownership contract

| ID | Capability | Canonical calculation owner | Canonical data | Deterministic impact |
|---|---|---|---|---|
| #8 | Seasonality | New derived validation/learning analytics, consuming existing history ownership | `Engine.bars`, Provider Router provenance, corporate-action truth | **NONE** |
| #18 | Signal Outcome Measurement | Existing `SignalValidationState` / `signal_validation.go`, refactored in place | frozen signal/evidence snapshot + post-snapshot canonical bars | **NONE** |

## 3. Historical cutoff semantics

1. Every replay owns an explicit `asOf` timestamp and an isolated data view.
2. A bar is eligible only when it was **completed and knowable** by `asOf`; a bar-start timestamp alone is insufficient if the bar was still forming.
3. News, SEC filings, earnings, macro releases, lifecycle events and provider corrections require a known/received/effective timestamp not later than `asOf`.
4. Present-day caches, current wall-clock time, current fundamentals or current event state cannot backfill historical truth.
5. If historical evidence cannot be reconstructed truthfully, the component is `UNAVAILABLE` or `PARTIAL`; current data is never substituted silently.
6. Outcome bars occur **after** the frozen decision and are never visible to the original decision calculation.

## 4. Exact replay vs scenario replay

- **Exact replay** is allowed only when DE.PULSE has enough frozen evidence/settings/provenance to reproduce what was knowable at that timestamp.
- **Scenario replay** may run the current frozen deterministic version over cutoff-filtered historical evidence, but it must be labeled `SCENARIO`, not “what DE.PULSE actually knew,” when original settings/evidence are unavailable.
- Legacy signal snapshots missing v16.3 freeze fields are migrated as `LEGACY / PARTIAL`; missing values are never fabricated.

## 5. Frozen signal snapshot contract (#18)

Forward snapshots must preserve at least:

- Symbol, horizon, timestamp, immutable snapshot ID and Evidence Snapshot ID.
- deterministic formula/version identity and material settings/profile fingerprint.
- Setup Score and Action.
- exact Entry Zone, invalidation and target(s) used at the decision time.
- price and required source/freshness truth at freeze time.
- material Market Intelligence and Event Intelligence state/evidence IDs where available.
- readiness/context fields already captured by the existing validation model.

A snapshot is immutable after freeze. Later provider corrections may affect outcome evidence if truthfully timestamped, but may not rewrite “what DE.PULSE knew then.”

## 6. Outcome state machine (#18)

Supported states: `PENDING`, `NO_ENTRY`, `INVALIDATED`, `TARGET_REACHED`, `PARTIAL`, `AMBIGUOUS`, `UNAVAILABLE`, `COMPLETE` as appropriate to the horizon/evidence.

Rules:

- Target before Entry Zone touch is **not success**.
- Entry touch must precede a target/invalidation success/failure sequence.
- If target and invalidation are both touched inside one coarse OHLC bar and finer canonical evidence is unavailable, result is `AMBIGUOUS`, not guessed.
- Day ordering should prefer eligible canonical intraday bars; daily OHLC must not invent intraday ordering.
- MFE/MAE are measured from a defined eligible reference/entry after the original setup is frozen.
- 1D/3D/5D/10D returns state their anchor and availability.
- Outcome analytics are not Portfolio, Journal or P&L.

## 7. Seasonality truth (#8)

Seasonality is descriptive context only. Initial professional scope is SPY/QQQ first; ticker/sector expansion is allowed only when canonical history and sample quality are defensible.

G1 minimum-sample policy for implementation:

- Month-of-year directional/frequency statistics: at least **8 completed years / 8 observations per month**; otherwise `INSUFFICIENT`.
- Day-of-week: at least **252 completed sessions total and 40 observations for the weekday**; otherwise `INSUFFICIENT`.
- Event-window seasonality: at least **20 comparable eligible events**; otherwise `INSUFFICIENT`.

Every result exposes sample count, date range, data coverage, source/freshness and limitations. Missing history is `UNAVAILABLE`, never zero. No seasonal result mutates Setup Score or Action.

## 8. Calibration truth (#19)

Calibration is descriptive and explicitly not probability conversion.

Group sample policy:

- `n < 30`: `INSUFFICIENT` — do not render confidence language.
- `30–99`: `LOW SAMPLE CONFIDENCE`.
- `100–299`: `MEDIUM SAMPLE CONFIDENCE`.
- `>=300`: `HIGHER SAMPLE DEPTH`, still not a claimed predictive probability.

Every output carries outcome definition, sample count, date range, missing/degraded handling and limitations. **Setup Score is not win probability.** Formula weights cannot auto-update from calibration.

## 9. Correlation / concentration truth (#26)

- Use aligned canonical **returns**, not quote-tick levels/noise.
- Require at least **60 aligned completed daily returns**; fewer => `UNKNOWN/INSUFFICIENT`.
- 60–125 aligned returns: low-sample context; >=126: normal descriptive window quality.
- Candidate concentration may use sector/industry mapping plus return correlation, but must not imply positions/P&L.
- High correlation raises attention/risk context only; it never automatically rejects a trade.

Initial descriptive attention bands may use absolute/positive correlation context such as `ELEVATED >= 0.70` and `HIGH >= 0.85`, always with sample/window visibility; these are attention labels, not trade rules.

## 10. Replay state-isolation contract (#20)

- Replay operates on cloned/isolated working state.
- No `saveCache`, settings write, watchlist write, Decision Queue mutation or live state publication from replay.
- Live analysis caches cannot be read unless keyed by the exact historical evidence/as-of identity.
- Replay cache, if used, is ephemeral and keyed by cutoff + evidence/version/policy identity.
- A before/after state fingerprint must prove production state restoration.
- Cancellation/failure must restore state as strictly as success.

## 11. UI / surface ownership

- **Market Intelligence:** compact market-level seasonality/concentration only when material.
- **Research:** selected-ticker outcome, validation and replay detail.
- **Decision Queue:** attention only for material validation/replay/concentration conditions; never opportunity quality.
- **Maintenance:** sample coverage, replay/data-job health, diagnostics.
- **Documentation:** methodology and limitations.
- **Dashboard:** compact summary only when decision-relevant; no default analytics sprawl.
- **No new top-level page** in G1.

## 12. Explicit unavailable/degraded semantics

Required public states include `UNAVAILABLE`, `INSUFFICIENT`, `PARTIAL`, `AMBIGUOUS`, `STALE/DEGRADED` where applicable. None may be rendered as zero, neutral, normal, successful or fresh.

## 13. Exclusions / hard stop rules

No Portfolio, Journal, P&L, brokerage, execution, autonomous trading, standalone Alerts, second Provider Router, second historical store, duplicate Evidence Snapshot, duplicate scoring engine, replay-only formula fork, v16.4+ scope, or automated formula learning.
