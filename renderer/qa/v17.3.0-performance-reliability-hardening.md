# DE.PULSE v17.3.0 TEST — Performance + Reliability Hardening

## Scope
This slice converts v17 runtime/load observability into measurable acceptance while preserving the immutable v16.11 Stable baseline and protected deterministic Day/Swing/Long formulas.

## Runtime SLOs
The canonical SLO owner now evaluates selected-symbol freshness, actionable-watchlist coverage, interactive API p95, provider/workload queues, CPU/memory/goroutines, provider request budgets, live subscription utilization, persistence queue/write rate, startup/warm-start coverage, storage growth, stale→current recovery and degradation recovery. Critical regular-session truth can block qualification when measured limits are materially breached.

## Efficiency evidence
Provider calls avoided are measured against actual provider request counts to expose canonical reuse. SQLite write activity is measured over a rolling one-minute window. Startup evidence records cache/persisted quote reuse and warm-start coverage without treating persisted state as timeless LIVE/CURRENT truth.

## Operations
Maintenance/Data Engine presents the same canonical diagnostics rather than introducing a second monitoring path. CPU is sampled from Go runtime metrics and all workload/provider queues remain bounded.

## Boundaries
No execution, brokerage, portfolio/P&L, journal, autonomous trading, authentication/multi-user, or v18 scope is introduced. Deterministic trading formulas are unchanged.
