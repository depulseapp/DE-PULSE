# DE.PULSE v16.0.4 - Checkpointed Certification Runner

Status: **Implemented as permanent build-process infrastructure.**

## Problem closed

Earlier v16.0.4 certification used umbrella commands for randomized/race/professional checks. The execution host could terminate a long wrapper after multiple constituent checks had already passed, forcing unnecessary repetition and making infrastructure termination look similar to a product failure.

## Permanent behavior

- Exact source fingerprint binds every PASS result to one immutable candidate.
- One process per expensive check.
- One log and JSON result per check.
- Resume skips exact-source PASS checkpoints.
- Source changes invalidate all prior PASS checkpoints automatically.
- PASS / PRODUCT FAIL / INFRA FAIL / BLOCKED are separate states.
- Randomized seeds `1600401` through `1600410` are ten independent checks.
- Race detector uses ten deterministic bounded shards.
- Coverage has a 50% statement floor for the v16.0.4 line.
- Previous-Build and Approved-Scope gates no longer hide redundant full/heavy suites inside themselves.
- Professional authorization reuses checkpointed constituent G10/G11 checks.
- Heavy/timing-sensitive checks are intended to run sequentially on the release host.

## Release-host prerequisite behavior

`release_environment_gate.py` uses `release_environment_policy.json`. For the 2026-08-11 v16.0.4 certification policy, supported Go minor lines are 1.25/1.26 with Go 1.26.5 preferred. `govulncheck` and native macOS/Windows acceptance are release blockers when unavailable. Those conditions are classified BLOCKED rather than PRODUCT FAIL.
