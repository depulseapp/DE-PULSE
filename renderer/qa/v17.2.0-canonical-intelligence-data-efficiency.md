# DE.PULSE v17.2.0 TEST — Canonical Intelligence + Data Efficiency

## Scope
This slice implements the v17 canonical intelligence/data-efficiency workstream while preserving the immutable v16.11 Stable baseline and protected deterministic Day/Swing/Long formulas.

## Canonical propagation
Every valid live quote can still update canonical in-memory state, bounded history, provider observations, and the lightweight UI path. Heavy downstream persistence/catalyst work is triggered only by the shared material-change policy. Runtime diagnostics expose received, material, suppressed, persistence-enqueue, and catalyst-evaluation counters.

## Lineage and feature-store truth
Frozen evidence and decision IDs are immutable in native SQLite, Windows system SQLite, and the fallback repository. Decision payloads no longer contain later outcome fields. Outcomes remain separate records linked to the frozen decision. Derived features update only when source hashes change, avoiding timestamp-only rewrites.

## OPEN-003 root cause closed in this slice
The Alpaca IEX stream previously acquired `Engine.mu.Lock()` before calling `multiFeedAllocation()`, which itself reads Engine state under `RLock()`. Go `RWMutex` is not re-entrant, so this could self-deadlock the live IEX processing path. v17.2 resolves allocation before taking the write lock and adds a deterministic regression test under normal and race execution.

## Boundaries
No execution, brokerage, portfolio/P&L, journal, autonomous trading, authentication/multi-user, or v18 scope is introduced. Deterministic trading formulas are not changed.
