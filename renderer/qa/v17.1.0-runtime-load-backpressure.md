## Implemented in this slice

- Tier 0–4 shared workload priority contract.
- Provider REST worker capacity with bounded queue and protected Tier 0/1 reserve.
- Per-tier queued/in-flight/rejected diagnostics.
- Cancellation-safe bounded waiting and explicit low-priority shedding.
- Broad Discovery routed as Tier 3; Opportunity Radar as Tier 2; normal actionable provider work as Tier 1; low-priority maintenance/background refresh as Tier 4.
- Work-tier context propagation for nested provider work.
- Alpaca/Finnhub live subscription capacity telemetry: capacity, normal target, reserve, active, available, reserve used, utilization and saturation.
- Attributable `LIVE CAPACITY SATURATED` degradation reason when runtime is degraded and a live pool has exhausted headroom.

## Safety / invariants

- Tier 0/1 is never automatically shed by local backpressure policy.
- Lower-priority work cannot consume provider capacity reserved for critical/actionable work.
- Queue length is hard-bounded; excess work is rejected rather than creating unbounded waiting goroutines/jobs.
- Existing provider subscription ceilings and allocation order remain unchanged.
- Deterministic Day/Swing/Long formulas are unchanged.
- No Execution Boundary is unchanged.

## Deferred / still open

- The v17.0 Windows JSON-fallback blocker is resolved in this source: Windows x64 uses the OS `winsqlite3.dll` SQLite backend and the Windows CGO-disabled compile gate passes. Native macOS packaged SQLite runtime still requires final package-host validation before Stable promotion.
- Provider-plan-specific RPM/credit ceilings are intentionally not hardcoded because entitlement varies. v17.1 measures request/minute, rate-limit pressure, concurrency and subscription capacity; provider-specific entitlement budgets remain router/configuration data rather than guessed constants.
- Deeper fetch-once/canonical-owner consolidation continues in v17.2.
