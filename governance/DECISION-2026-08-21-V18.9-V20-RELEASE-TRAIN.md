# DECISION — v18.9 → v20 Dependency-First, Cross-Platform Lockstep Release Train

**Status:** APPROVED / MERGED VIA PR #67  
**Date:** 2026-08-21  
**Does not authorize:** v19 implementation before ordered v18.9.x closure.

## Context

The v18.9→v20 architecture audit corrected provider-observability ordering, duplicate #66 placement, obsolete hosted-version reservations, hosted rights/entitlement/privacy separation, IaC/environment assurance and software-supply-chain ownership.

A further cross-platform audit found one structural weakness: the plan still used a `macOS pilot -> Windows parity -> Web parity` sequence. That made final parity mandatory but allowed avoidable product drift during implementation and encouraged platform catch-up work.

DE.PULSE is intended to be one product across macOS, Windows and Web. Shared product capabilities therefore require one canonical contract and lockstep delivery across all applicable supported clients.

## Decision

Adopt this permanent sequence:

`stabilize -> canonicalize -> instrument -> validate -> expand -> operationalize -> close -> hosted rights/identity/entitlement/privacy/IaC/data foundations -> provider gateway/serving/sync foundations -> cross-platform shared capability -> equivalence certification -> next cross-platform shared capability -> mixed-client hardening -> point-in-time evidence -> reliability/readiness -> governed adaptive intelligence`

### Cross-Platform Lockstep Contract

For every G1 capability scope:

`capability -> canonical owner -> macOS REQUIRED/N/A -> Windows REQUIRED/N/A -> Web REQUIRED/N/A`

Rules:
1. Shared capabilities are designed once against canonical domain/API/state truth.
2. All REQUIRED platform adapters/surfaces belong to the same capability release responsibility.
3. Platform-specific adapters may differ only where OS/browser mechanics require it.
4. Business logic, intelligence, state semantics, authorization, product entitlement, provider-right decisions, freshness/provenance and user-visible meaning cannot fork by platform.
5. One-platform technical validation is diagnostic only; it is not a product pilot and cannot satisfy delivery.
6. A shared capability cannot pass G10/G15 or be called Delivered/GA while a REQUIRED supported platform is materially behind.
7. No next shared domain starts while the current shared domain has material parity debt.
8. A temporary platform exception requires a proven external blocker, explicit waiver/expiry, no misleading GA claim and a durable recovery release.
9. Platform-specific corrective work remains allowed when the actual responsibility is platform-specific, such as the macOS `v18.9.1` crash.

## Hosted serving model — independent controls

Never collapse these into one generic entitlement flag:
1. tenant/account identity;
2. RBAC/capability authorization;
3. DE.PULSE product entitlement/plan/quota;
4. upstream provider legal/data rights;
5. privacy/data-governance policy.

## G0-G16 enforcement

No G17+.

- G2 prevents duplicate client business owners.
- G3 freezes one canonical contract + adapter contracts/equivalence tests.
- G4 requires all REQUIRED client implementations for a shared capability.
- G6 proves cross-platform state/API integration.
- G7 proves equivalent authorization/data/privacy/right outcomes.
- G8 proves mixed-client capacity/recovery where applicable.
- G9 proves UX/function/meaning equivalence.
- G10 blocks on material parity debt.
- G13/G14 validate actual required native/Web artifacts/deployments.
- G15 forbids shared-capability GA until all REQUIRED clients pass.
- G16 audits parity drift and any temporary waivers.

## Version semantics

Major = strategic maturity generation. Minor band = coherent dependency phase. Patch = one primary independently certifiable responsibility. A shared capability's required platform adapters are part of that responsibility, not separate features. Future reservations may shift before G1; shipped releases never move.

## Protected boundaries

G0-G16 only; U.S. Equities Processing; GLD/SLV/USO actionable exceptions; No Execution; Smart Provider Router v2 sole routing authority; canonical freshness/cache/persistence/subscription/session/SEC/identity owners; direct SEC/EDGAR authority; deterministic Day/Swing/Long protection; SHADOW -> VALIDATED -> APPROVED -> PRODUCTION; protected pre-market/regular-market/after-hours priority.

## Supersession

This decision supersedes earlier future placement that used `macOS pilot -> Windows parity -> Web parity`. It does not rewrite shipped history or remove any approved capability. It changes only unstarted future planning so DE.PULSE remains one consistent product.
